# 前端编码规范与最佳实践

## 文档说明

本文档基于 **Ant Design 5.19.3** 和 **Ant Design Pro** 制定，旨在指导开发者编写高质量、可维护、可扩展的前端代码。

**核心内容**：
- **主题适配**：亮色/暗色/紧凑模式自动适配
- **组件规范**：ProComponents 使用规范和最佳实践
- **现代化重构**：Flex 布局等现代化组件迁移指南
- **代码质量**：编码规范、检查清单、常见问题

## 一、核心开发原则

### 基本原则

> **规范的代码可以自动适配主题，不规范的代码会让维护工作量增加数十倍甚至上百倍。**

在开发过程中，请始终遵循以下核心原则：

1. **使用 Less 模块**组织样式，避免内联样式
2. **使用 theme.useToken()**处理动态样式
3. **使用 CSS 变量**而非硬编码颜色（如 `#fff`、`#262626`）
4. **使用 useApp() hook**而非静态方法（message/modal/notification）
5. **使用 ProForm 组件的 formRef**而非 Form.useForm()
6. **不修改 ProComponents** 的样式 props（会导致级联影响）
7. **设计阶段就考虑主题适配**，而非事后补救

### ProComponents 特别注意

> **ProComponents 组件会自动适配主题，不要添加显式的样式属性。**

**禁止操作**：
```typescript
// ❌ 不要这样做
<ProCard
  style={{ background: 'var(--ant-color-bg-container)' }}
  headStyle={{ background: 'var(--ant-color-bg-container)' }}
  bodyStyle={{ padding: 16 }}
/>
```

**原因**：
- ProComponents 内部使用全局状态或 context 管理主题
- 显式设置样式可能干扰这个机制
- 可能导致其他页面出现级联影响

**正确做法**：
```typescript
// ✅ 让组件自动适配主题
<ProCard>
  <ProTable />
</ProCard>

<PageContainer>
  内容
</PageContainer>
```

## 二、Ant Design 5 主题系统概述

### 核心特性

Ant Design 5 引入了全新的主题系统，提供以下特性：

1. **Design Token 体系**：基于设计令牌的主题定制
2. **CSS-in-JS**：完整的 CSS 变量支持
3. **动态主题切换**：运行时无缝切换主题
4. **TypeScript 类型支持**：完整的类型提示
5. **预设算法**：默认、暗色、紧凑三种算法

### 三种预设算法

```typescript
import { theme } from 'antd';

// 1. 默认算法（亮色主题）
theme.defaultAlgorithm

// 2. 暗色算法
theme.darkAlgorithm

// 3. 紧凑算法（更小的组件尺寸）
theme.compactAlgorithm

// 可以组合使用
[theme.darkAlgorithm, theme.compactAlgorithm] // 暗色 + 紧凑
```

### 主题变量层级

```typescript
const { token } = theme.useToken();

// token 对象包含所有主题变量：
token.colorPrimary      // 主题色
token.colorSuccess      // 成功色
token.colorWarning      // 警告色
token.colorError        // 错误色
token.colorInfo         // 信息色
token.colorText         // 主文本色
token.colorTextSecondary // 次要文本色
token.colorTextTertiary  // 第三级文本色
token.colorBorder        // 边框色
token.colorBgContainer   // 容器背景色
token.colorBgLayout      // 布局背景色
// ... 更多
```

## 三、规范的开发方式

### ✅ 方式一：使用 theme.useToken() Hook（推荐）

**适用场景**：需要动态计算样式或根据状态改变颜色时

```typescript
import { theme } from 'antd';

const MyComponent: React.FC = () => {
  const { token } = theme.useToken();

  // 动态颜色计算
  const getStatusColor = (status: string) => {
    switch (status) {
      case 'success': return token.colorSuccess;
      case 'warning': return token.colorWarning;
      case 'error': return token.colorError;
      default: return token.colorTextSecondary;
    }
  };

  return (
    <div style={{ color: getStatusColor(currentStatus) }}>
      {content}
    </div>
  );
};
```

**优点**：
- ✅ 完整的 TypeScript 类型支持
- ✅ 自动跟随主题变化
- ✅ 适合动态计算场景

---

### ✅ 方式二：使用 Less 模块 + CSS 变量（推荐）

**适用场景**：静态样式定义

#### 第一步：创建 Less 文件

```less
// Component.less
.container {
  background: var(--ant-color-bg-container);
  border: 1px solid var(--ant-color-border);
  padding: 16px;
}

.title {
  font-size: 14px;
  font-weight: 500;
  color: var(--ant-color-text);
}

.description {
  font-size: 12px;
  color: var(--ant-color-text-secondary);
}

// 状态样式
.status {
  &.success {
    color: var(--ant-color-success);
  }

  &.warning {
    color: var(--ant-color-warning);
  }

  &.error {
    color: var(--ant-color-error);
  }
}
```

#### 第二步：在组件中使用

```typescript
import styles from './Component.less';
import classNames from 'classnames';

const MyComponent: React.FC = () => {
  return (
    <div className={styles.container}>
      <div className={styles.title}>标题</div>
      <div className={styles.description}>描述文本</div>
      <div className={classNames(styles.status, styles.success)}>
        成功状态
      </div>
    </div>
  );
};
```

**优点**：
- ✅ 样式代码集中管理
- ✅ 可复用性强
- ✅ 利用 CSS 缓存优化性能
- ✅ 支持嵌套和选择器

### ✅ 方式三：结合使用（最佳实践）

**静态样式用 Less，动态样式用 token**

```typescript
import { theme } from 'antd';
import classNames from 'classnames';
import styles from './Component.less';

const MyComponent: React.FC = () => {
  const { token } = theme.useToken();

  return (
    <div className={styles.container}>
      {/* 静态样式使用 Less */}
      <div className={styles.title}>标题</div>

      {/* 动态样式使用 token */}
      <div style={{ color: isActive ? token.colorPrimary : token.colorTextSecondary }}>
        {isActive ? '激活' : '未激活'}
      </div>
    </div>
  );
};
```

### ✅ 方式四：使用 Flex 组件替代 Row/Col（现代化布局）

**状态**：⏳ 待启动 - 可渐进式迁移 Row/Col 布局

**适用场景**：需要灵活布局的场景，替代传统的 Row/Col 栅格系统

#### 为什么使用 Flex 组件？

**优势说明**：
1. **更简洁的 API**：直接使用 flexbox 属性，无需计算栅格数（span）
2. **更好的响应式支持**：自动适配容器大小，无需手动设置断点
3. **更直观的代码**：CSS flexbox 语义化属性，易读易维护
4. **更小的包体积**：Ant Design 5 原生组件，无额外依赖
5. **更好的主题适配**：完美集成 Design Token 系统

#### 常用属性对照表

| Row/Col 属性 | Flex 属性 | 说明 |
|-------------|----------|------|
| `gutter={16}` | `gap={16}` | 间距设置 |
| `gutter={[16, 8]}` | `gap="16px 8px"` | 水平和垂直间距 |
| `justify="start"` | `justify="flex-start"` | 主轴对齐 |
| `align="top"` | `align="flex-start"` | 交叉轴对齐 |
| `Col span={12}` | `style={{ flex: '0 0 50%' }}` | 固定宽度比例 |
| - | `flex={1}` | 自动填充剩余空间 |
| - | `vertical` | 垂直布局 |
| - | `wrap="wrap"` | 自动换行 |

#### 实际应用示例

**示例 1：表单操作栏**
```typescript
// ✅ 使用 Flex
<Flex justify="flex-end" gap={8}>
  <Button>取消</Button>
  <Button type="primary">确定</Button>
</Flex>
```

**示例 2：卡片头部**
```typescript
// ✅ 使用 Flex
<Flex justify="space-between" align="center">
  <div>
    <h3>标题</h3>
    <p>描述信息</p>
  </div>
  <Button>操作</Button>
</Flex>
```

**示例 3：响应式网格**
```typescript
// ✅ 使用 Flex
<Flex gap={16} wrap="wrap">
  {items.map(item => (
    <div key={item.id} style={{ flex: '0 0 calc(25% - 12px)' }}>
      <Card>{item.content}</Card>
    </div>
  ))}
</Flex>
```

#### 迁移检查清单

**计划阶段**：
- [ ] 识别项目中所有使用 Row/Col 的布局
- [ ] 评估迁移优先级（新页面优先，复杂布局可延后）
- [ ] 确认不影响现有功能

**开发阶段**：
- [ ] 替换 `<Row>` 为 `<Flex>`
- [ ] 将 `gutter` 改为 `gap`
- [ ] 移除 `<Col>` 包装，直接使用内容元素
- [ ] 使用 `flex` 样式属性替代 `span` 计算
- [ ] 调整对齐属性（justify/align）

**测试阶段**：
- [ ] 验证不同屏幕尺寸下的布局效果
- [ ] 测试亮色/暗色主题下的显示
- [ ] 确认间距和对齐符合设计要求
- [ ] 检查浏览器兼容性（现代浏览器均支持）

**优点**：
- ✅ 代码更简洁直观
- ✅ 减少 DOM 层级（少一层 Col 包装）
- ✅ 更好的性能（原生 CSS flexbox）
- ✅ 完美的主题适配

### ✅ 方式五：使用 Splitter 分隔面板（可拖拽布局）

#### 基本用法

使用 `Splitter` 替代 `ProCard split="vertical"` 实现可拖拽的分栏布局：

```tsx
import { Splitter } from "antd";
import useResponsiveLayout from "@/hooks/useResponsiveLayout";

const MyPage: React.FC = () => {
  const layout = useResponsiveLayout({ breakpoint: "xl" });

  return (
    <Splitter layout={layout} className={styles.splitterContainer}>
      <Splitter.Panel
        defaultSize="25%"
        min={180}
        max="45%"
        collapsible={{ start: true }}
      >
        <ProCard title="左侧">内容</ProCard>
      </Splitter.Panel>
      <Splitter.Panel min={600} max="80%">
        <ProCard>右侧</ProCard>
      </Splitter.Panel>
    </Splitter>
  );
};
```

**Less 样式**：
```less
.splitterContainer {
  height: calc(100vh - 200px);
  min-height: 600px;

  .leftPanel,
  .rightPanel {
    display: flex;
    flex-direction: column;
    height: 100%;

    :global(.ant-pro-card) {
      display: flex;
      flex-direction: column;
      height: 100%;
      border: none;

      :global(.ant-pro-card-body) {
        flex: 1;
        overflow: auto;
      }
    }
  }
}
```

#### 参数推荐值

| 场景 | 左侧 min | 左侧 defaultSize | 右侧 min | 断点 |
|------|----------|------------------|----------|------|
| 标准组织树 | 180 | 25% | 600 | xl |
| 深层级组织树 | 380 | 30% | 600 | xl |
| 三栏布局 | 180 | 20% | 480/520 | xxl |

**重要**：
- `min` 和 `max` 使用数字时表示像素（如 `min={180}`），不要用字符串（如 `min="180px"`）
- 百分比用字符串（如 `max="45%"`）
- 应用导航栏在 < 1200px 自动收起（已在 `app.tsx` 配置）


## 七、常见问题 FAQ

### Q1：什么时候可以使用内联样式？

**A**：仅在以下情况下使用：
1. 需要动态计算的位置属性（`left`、`top`、`width` 等）
2. 必须使用 JavaScript 计算的样式
3. 一次性使用的特殊样式

```typescript
// ✅ 合理的内联样式使用
<div style={{ left: `${position}px`, width: `${width}px` }}>
```

### Q2：CSS 变量和 token 有什么区别？

**A**：
- **CSS 变量**：在 Less/CSS 文件中使用，无类型检查
- **token**：在 TypeScript 中使用，有完整类型检查

```less
/* Less 文件中 */
.container {
  color: var(--ant-color-text);  /* CSS 变量 */
}
```

```typescript
/* TypeScript 文件中 */
const { token } = theme.useToken();
<div style={{ color: token.colorText }}>  {/* token 对象 */}
```

### Q3：如何调试主题相关问题？

**A**：
1. 使用浏览器开发工具查看计算后的样式
2. 检查 CSS 变量是否正确应用
3. 确认是否有 `!important` 覆盖了样式
4. 强制刷新浏览器清除缓存

### Q4：修改后其他页面出问题怎么办？

**A**：
1. **立即回退修改**（`git checkout`）
2. 不要试图通过更多修改来"修复"
3. 重新评估是否真的需要修改
4. 考虑使用非侵入性方案（Less 类而非组件 props）

### Q5：为什么表单提交后再次打开会残留数据？

**A**：确保三点：
1. ProForm 使用 `formRef` 而非 `Form.useForm()`
2. 设置 `drawerProps={{ destroyOnHidden: true }}`
3. 在 `onOpenChange` 中按顺序重置：formRef → state → callback

### Q6：Form.useForm() 和 formRef 有什么区别？

**A**：ProForm 系列组件必须用 `formRef`，原生 Form 用 `Form.useForm()`。ProForm 内部有额外的状态管理，使用 formRef 确保生命周期同步

## 八、ProTable 表格开发规范

### 设计原则

> **表格是数据展示的核心组件，统一的实现方式能显著提升用户体验和代码可维护性。**

### 操作列规范

#### 1. 操作列定义

**必须使用 `valueType: "option"`**（ProTable 官方推荐）：

```typescript
// ✅ 正确
{
  title: '操作',
  valueType: 'option',
  width: 150,
  fixed: 'right',
  render: (_, record) => (/* 操作按钮 */)
}

// ❌ 错误
{
  title: '操作',
  key: 'action',
  search: false,  // 不推荐，应使用 valueType: 'option'
  render: (_, record) => (/* 操作按钮 */)
}
```

#### 2. 操作按钮样式

**统一使用 `<Button type="link" size="small">`**：

```typescript
// ✅ 正确
<Button type="link" size="small" icon={<EditOutlined />} onClick={() => onEdit(record)}>
  编辑
</Button>
<Button type="link" size="small" danger icon={<DeleteOutlined />} onClick={handleDelete}>
  删除
</Button>

// ❌ 错误 - 不要使用 a 标签
<a onClick={() => onEdit(record)}>
  <EditOutlined /> 编辑
</a>
<a style={{ color: token.colorError }} onClick={handleDelete}>
  <DeleteOutlined /> 删除
</a>

// ❌ 错误 - 不要使用默认大小的 Button
<Button type="link" icon={<EditOutlined />}>编辑</Button>
```

#### 3. 危险操作确认

**删除、解绑等危险操作必须有确认弹窗**：

```typescript
// ✅ 方式一：Popconfirm（适合简单确认）
<Popconfirm
  title="确认删除？"
  description="删除后无法恢复，请谨慎操作。"
  onConfirm={() => onDelete(record)}
  okText="确认"
  cancelText="取消"
>
  <Button type="link" size="small" danger icon={<DeleteOutlined />}>
    删除
  </Button>
</Popconfirm>

// ✅ 方式二：Modal.confirm（适合需要更多说明的场景）
const handleDelete = () => {
  Modal.confirm({
    title: '确定要删除此配置吗？',
    content: '删除后将无法恢复',
    okText: '确定',
    cancelText: '取消',
    okButtonProps: { danger: true },
    onOk: () => onDelete(record),
  });
};

// ❌ 错误 - 危险操作没有确认
<Button type="link" size="small" danger onClick={() => onDelete(record)}>
  删除
</Button>
```

#### 4. 操作按钮数量与布局

| 操作数量 | 推荐布局 |
|---------|---------|
| 1-3 个 | 直接平铺展示 |
| 4+ 个 | 常用操作平铺 + Dropdown 收纳其他 |

```typescript
// ✅ 操作较多时使用 Dropdown 收纳
<Space size="small">
  <Button type="link" size="small" icon={<EyeOutlined />} onClick={() => onView(record)}>
    详情
  </Button>
  <Dropdown menu={{ items: moreMenuItems }} trigger={['click']}>
    <Button type="link" size="small" icon={<MoreOutlined />}>
      更多
    </Button>
  </Dropdown>
</Space>
```

### 独立 Actions 组件

当操作逻辑复杂时，抽取独立的 `TableActions` 组件：

```typescript
// components/XxxTableActions.tsx
interface XxxTableActionsProps {
  record: DataType;
  onView: (record: DataType) => void;
  onEdit: (record: DataType) => void;
  onDelete: (record: DataType) => void;
}

const XxxTableActions: React.FC<XxxTableActionsProps> = ({
  record,
  onView,
  onEdit,
  onDelete,
}) => {
  const handleDelete = () => {
    Modal.confirm({
      title: '确定要删除吗？',
      content: '删除后无法恢复',
      okButtonProps: { danger: true },
      onOk: () => onDelete(record),
    });
  };

  return (
    <Space size="small">
      <Button type="link" size="small" icon={<EyeOutlined />} onClick={() => onView(record)}>
        查看
      </Button>
      <Button type="link" size="small" icon={<EditOutlined />} onClick={() => onEdit(record)}>
        编辑
      </Button>
      <Button type="link" size="small" danger icon={<DeleteOutlined />} onClick={handleDelete}>
        删除
      </Button>
    </Space>
  );
};
```

2. **查找对应版本的文档**
   - 优先查看项目实际使用版本的文档

4. **验证 API 的正确性**
   - 在项目中小范围测试后再大面积应用
   - 遇到问题时查看控制台错误信息
